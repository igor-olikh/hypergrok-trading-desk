# Проверка IBKR 13 октября 2026

Итог живой проверки бумажного счёта на MacBook Pro. Личных данных здесь нет: ни номера счёта, ни имени входа, ни баланса, ни заявок.

## Вывод

Путь Interactive Brokers в этом проекте ещё не рабочий.

Вход в портал брокера живой. Бумажный счёт один, программа его видит. Цену акции прочитать не удалось. Заявка не отправлялась.

22 проверки `python3 scripts/test_ibkr.py` зелёные. Они идут на выдуманном брокере в памяти и в интернет не ходят.

## Что было запущено

Официальный Client Portal Gateway, архив `clientportal.gw.zip` со страницы брокера. Содержимое архива датировано 24 апреля 2023. Это не торговая программа TWS.

Java на машине: OpenJDK 25.0.2. При старте Java пишет предупреждение про `sun.misc.Unsafe`. Шлюз после этого всё равно поднялся.

Порт 5000 на этом Mac занят службой AirPlay. В `root/conf.yaml` стоит `listenPort: 5001`. Страница входа: `https://localhost:5001`.

Сервер брокера в ответе статуса представился сборкой `Build 10.50.1a, Sep 23, 2026`. Старый шлюз говорит с новым сервером. Это наблюдение, не доказанная причина сбоя.

## Что ответил брокер

Две разные двери.

1. Вход в портал. `GET /sso/validate` вернул `RESULT: true`. `GET /portfolio/accounts` вернул один счёт, и он бумажный.
2. Торговая сессия и цены. Сама по себе она не открывается. Её открывает `POST /iserver/auth/ssodh/init` с `publish: true` и `compete: true`. После этого `authenticated` и `established` становятся `true`.

Бумага SPY находится. Контракт есть, биржа SMART, валюта USD.

Канал цен не поднялся. Служебный `POST /tickle` всю сессию возвращал `hmds.error = "no bridge"`.

Снимок цены ведёт себя так:

1. `GET /iserver/accounts` возвращает 200.
2. Первый `GET /iserver/marketdata/snapshot` по SPY возвращает 200 и пустое тело, без цены.
3. Следующий снимок возвращает HTTP 500 и текст `Please query /accounts first`.
4. Торговая сессия после этого гаснет: `authenticated` снова `false`. Вход в портал при этом остаётся живым.

Список счетов уже был запрошен и ответил успехом. Текст ошибки 500 этого не объясняет. Канал `no bridge` при этом не исчезал.

Код доступности цены `6509` (живая, задержанная, нет подписки) ни разу не пришёл. Поэтому вывод «нужно купить подписку на цены» из этой проверки не следует.

## Дыры в коде проекта

Команда цены их не закрывает. Это проверено по `scripts/ibkr_client.py`.

- `get_quote` сразу идёт в снимок. Он не вызывает `POST /iserver/auth/ssodh/init`.
- `get_quote` не вызывает `GET /iserver/accounts` перед снимком. Инструкция брокера этот вызов требует. Ручной вызов в этой проверке ошибку 500 не снял.
- Повтор снимка есть только если первый ответ совсем пустой. Если брокер ответил 500, наружу уходит общая фраза «quote is unavailable», без текста брокера.
- `auth_status` ходит методом GET. У брокера рабочий статус торговой сессии — POST `/iserver/auth/status`.
- Проверка врача из-за этого легко пишет `FAIL ibkr auth`, даже когда вход в портал уже есть.
- Потолки риска (1% на сделку и остальные) лежат в `ibkr_risk.py`. Команда отправки `ibkr_execute.py` их не вызывает: в неё не передаётся состояние счёта.
- Семь ролей и навыки по-прежнему про крипто-стол Hyperliquid. Сами они заявку в IBKR не готовят.

## Что делать дальше

1. Закрыть TWS, сайт брокера и приложение на телефоне. Цены и торговля у брокера идут только в одну сессию.
2. Войти заново на `https://localhost:5001` бумажным логином. Если страница предлагает вход с торговлей и ценами, выбрать его.
3. Снова прочитать `POST /tickle`. Готово только если `hmds.error` больше не равен `no bridge`, а повторный снимок SPY содержит поле `31` и сессия остаётся `authenticated: true`.
4. После этого поправить `get_quote`: открыть торговую сессию, запросить счета, повторить снимок и показать настоящий текст ошибки брокера.
